# 스테어 엔지니어링 (Stair Engineering) — 한국어 안내

**[English →](README.md)**

**항상 읽는 것은 얇게, 깊은 지식은 계단 위에.**

AI 에이전트(혹은 여러 명의 팀)가 매 호출마다 무엇을 읽을지를 정리하는 작고 도구-무관한 방법이다.
15인 에이전트 팀을 운영하다 나온 것으로, 공용 "헌장"이 21.5KB까지 자라 매 메시지마다 통째로 주입되던 상황 — 일부 도구가 잘라내기 시작했고 에이전트들이 규칙을 조용히 잃던 사고 — 에서 출발했다.

해결은 더 큰 컨텍스트 창이 아니라 계단이었다.

```
4층  런타임     코드가 매 호출 끼워 넣는 것 — 오늘 날짜, 지금 쓸 수 있는 도구, 최근 대화
3층  정체성     에이전트마다 카드 한 장 — 누구인지, 어떻게 말하는지
2층  지식       호(號) 주소로 부르는 방(201, 202, 204…) — 필요할 때만, 절 단위로 연다
1층  메모리     딱 한 장 — 매 호출 항상 주입
0층  작업메모   지금 이 창이 하는 일 — 창마다 한 파일, 자동으로 안 읽힌다
```

★**항상 읽는 건 1층 하나뿐이다.** 1층 위의 것은 전부 *주소*("201호 색인 절")로 찾는다.
스크롤로 찾지 않는다.

4층이 왜 따로 있냐면 — 1·2·3층은 **네가 파일에 써 넣은 것**이고, 4층은
**프로그램이 매번 자동으로 끼워 넣는 것**이다. 파일 어디에도 없다.

가장 쉬운 예가 **오늘 날짜**다. 모델은 오늘이 며칠인지 모른다. 그렇다고 파일에
"오늘은 8월 20일" 이라고 적어두면 **내일 틀린다.** 그래서 코드가 매번 그날 날짜를 넣는다.

★이 층이 중요한 이유는 둘이다.

**하나 — 안 보이는데 값은 나간다.** 프롬프트 파일을 아무리 줄여도 컨텍스트가 안 줄어드는 이유가 이것이다.
날짜 한 줄, 도구 목록, 최근 대화 몇 개가 매 호출 조용히 붙는다. **세지 않으면 절약한 만큼 도로 먹힌다.**

**둘 — 여기가 "규칙도 지식도 아닌 것" 을 넣는 유일한 자리다.** 최근 이력이 정확히 그 모양이다.
*세 시간 전에 무엇을 고쳤는가* 는 항상 참인 규칙이 아니라서 1층에 못 넣고, 에이전트가 찾아볼 생각을
하지 않으니 2층으로도 안 닿는다. ★이 칸을 비워두면 **에이전트가 자기가 방금 한 일을 못 떠올린다** —
그리고 왜 그런지 둘 다 모른다. 긴 세션은 아무도 누르지 않아도 스스로 접히기 때문이다.

고치는 방법은 더 열심히 기억하는 게 아니라 **매 세션 시작과 매 압축 때 코드가 배달하게** 만드는 것이다.

0층이 왜 따로 있냐면 — "지금 A업체 블로그를 고치는 중이고 어제 3번까지 했다" 같은 메모는
**다른 작업엔 쓸모가 없다.** 그런데 1층에 적으면 **모든 작업이 그걸 같이 읽는다.**
그래서 이 작업에만 딸리는 메모는 계단 맨 아래에 따로 두고, **자동으로 안 읽히게** 한다.
필요한 창에서만 연다. 사무실 벽에 붙은 규칙(1층)과
지금 하는 일 위에 얹어둔 포스트잇(0층)의 차이다. 포스트잇은 일이 끝나면 뗀다.

## 누구를 위한 건가

AI 와 사람 둘 다. 특히 개발 경험 없이 AI 로 만드는 사람들(바이브 코딩)을 위해 — 내 에이전트가 항상 읽는 게 뭔지 **한 장으로 보이고**, 어떤 지식이 어디 있는지 **호 번호로 찾고**, 코드 안 건드리고 **md 파일 고치고 명령 하나로 갱신**할 수 있어야 한다. 사람이 1분 안에 못 읽는 장이면 에이전트에게도 너무 긴 것이다.

## RAG랑 뭐가 다른가
- **유사도가 아니라 주소.** 사람이 읽을 수 있는 호 번호와 절 제목. 에이전트가 "그건 201호 순위 절에 있다"고 *말할 수 있고*, 사람이 5초 만에 확인할 수 있다.
- **한 장 규칙을 사람 의지가 아니라 도구가 지킨다.** `stair_toc.py check`가 아무도 못 찾는 방(라우트 없음), 없는 파일을 가리키는 라우트, 1층 크기를 알려준다.
- **절 단위 로딩.** 25KB 방을 통째로 열면 1층 열 장 값이다. 방마다 목차가 자동으로 붙고, 로더는 목차를 먼저 주고 요청한 절 하나만 준다.
- **파일을 못 읽는 에이전트도 쓴다.** 로더 출력이 평문이라 시스템 프롬프트·CLAUDE.md·AGENTS.md·.cursorrules·Ollama Modelfile 어디든 붙는다.

## 실측 (약속이 아니라)
| 항목 | 전 | 후 |
|---|---|---|
| 매 호출 상시 주입 | 21,543B 헌장 | 1층 9.6~11KB (래퍼 3,620→234자) |
| 가장 가벼운 에이전트(파일시스템 없음·전부 인라인) 호출당 프롬프트 | ~2,900자 | 1,111자 (−62%) |
| 전달 중 규칙 훼손 | 있었음(헌장 잘림) | 같은 날 한 번 더 있었음(멘션 토큰 정리기가 1층 두 줄을 비움) — 검수 에이전트가 한 시간 안에 잡아 원인 수정. 계단은 사고를 *보이게* 했지 불가능하게 하진 않았다 |
| 아무도 못 찾는 파일 | 알 수 없음 | 0 (도구가 검사) |
| 호스트 간 사본 어긋남 (지식 사본) | 한 호스트에 24개 중 10개 | 24/24 전 호스트, 자동 동기, 개수로 검증 |

이 숫자는 **우리 운영팀의 하루 전후**지 이 저장소 것이 아니다 — 여기 예시 1층은 2.5KB 라 `check` 는 그 값을 찍는다. 네 숫자는 다를 것이고, 도구가 매번 1층 크기를 보여준다.
크기 참고: 우리 1층이 9~11KB 인 건 3대 머신·15 에이전트 규칙을 담아서다. 에이전트 하나·머신 하나면 훨씬 작아야 하고, 로컬 모델은 ~3KB 아래를 목표로.

## 60초 시작
```bash
python3 tools/stair_load.py                          # 1층 — 시스템 프롬프트에 붙여라
python3 tools/stair_load.py --agent researcher       # + 정체성 카드
python3 tools/stair_load.py --route "순위 확인"       # + 키워드로 고른 방의 목차
python3 tools/stair_load.py --room 201 --section indexing   # + 절 하나만
python3 tools/stair_toc.py check                     # 계단이 정직한가
```
파이썬 3.8+, 의존성 없음, 네트워크 없음.

## 쓰는 도구에 붙이는 법

`python3 tools/stair_load.py --install` 을 인자 없이 치면 **폴더 안의 모든 에이전트 파일**을 찾아 갱신한다.

| 도구 | 파일 |
|---|---|
| Claude Code | `CLAUDE.md` |
| Codex CLI / OpenAI 계열 | `AGENTS.md` |
| Gemini CLI | `GEMINI.md` |
| Antigravity · 그 외 | `AGENT.md` |
| Cursor · Cline · Windsurf | `.cursorrules` · `.clinerules` · `.windsurfrules` |
| GitHub Copilot | `.github/copilot-instructions.md` |
| Grok Build | `GROK.md` |

경로가 다르면 `--install 파일이름` 으로 찍어주면 된다.
`--install` 은 `STAIR:BEGIN` / `STAIR:END` 사이에 **관리 블록만 덧붙인다** — 원래 쓰던 규칙은 그대로 남고,
다시 돌리면 그 블록만 새로 고쳐진다. 먼저 보고 싶으면 `--dry-run`.

**올라마 · LM Studio · 그냥 API · 파일이 없는 채팅 UI** — `python3 tools/stair_load.py` 를 돌려서
나온 것을 시스템 프롬프트 칸에 붙인다. 1층을 고치면 다시 붙인다.
★로컬 모델은 1층 크기가 더 중요하다. **3KB 아래**를 목표로.

★**여기서 놓치기 쉬운 것** — 그 블록에는 **나머지 층을 여는 방법**(`--route`, `--room`, `--agent`)도 들어 있다.
이게 없으면 에이전트는 1층만 쥔 채 **방이 있다는 걸 영영 모른다.** 그래서 계속 기억으로 답하고,
계단은 폴더에만 남는다. ★**폴더를 복사한 건 설치가 아니다** — 에이전트가 실제로 읽는 파일에
`STAIR:BEGIN` 블록이 있는지 확인하고, 1층을 고칠 때마다 `--install` 을 다시 돌려라.

## 계단을 눈으로 봐라

`python3 tools/build_viewer.py` 를 돌리면 **혼자 도는 `stairs.html` 한 장**이 나온다.
서버도 빌드도 네트워크도 필요 없다. 더블클릭하면 층·파일·절이 **로더가 에이전트에게 주는 순서 그대로** 보인다.

★이게 터미널이 못 주는 절반이다. **코드를 안 쓰는 사람이** 그 화면을 보고
"저 규칙은 자리가 틀렸네" 라고 말할 수 있다는 것 — 그게 이 방식의 요점이다.

`stairs/` 를 고치면 다시 돌려라.

### 혼자 일한다면 3층은

혼자여도 모자는 바뀐다 — 코드 쓸 때, 검토할 때, 글 쓸 때 태도가 다르다.
보통은 그 태도를 매번 다시 치거나, 늘 읽히는 1층에 붙여서 뚱뚱하게 만든다.
★**모드마다 카드 하나**가 둘 다 푼다. 그 작업에만 태도를 붙이고 1층은 얇게 유지한다.

★3층은 선택이다. 늘 한 가지 방식으로만 일한다면 그 두 줄은 1층에 두고 이 층은 건너뛰어라.
**빈 층이 있는 계단은 짧은 계단보다 나쁘다.**

## 규칙 다섯
1. 1층은 한 장. 자라면 규칙을 방으로 옮기고 한 줄만 남겨라. 도구가 크기를 찍어준다.
2. 주소록 밖엔 아무것도 없다. 1층(또는 routes.txt)에 라우트 없는 방은 존재하지 않는 것. check가 잡는다.
3. 모든 방에 목차. 자동 생성·멱등. 목차 먼저, 절 하나만.
4. 배선을 바꾸면 204호에 한 줄. 시스템의 역사는 채팅이 아니라 시스템 안에.
5. 정본은 한 곳. 여러 머신이면 한 머신이 소유하고 사본을 민다. 밀고 나서 개수로 검증한다.

## 누구나 처음 하는 실수 (우리도 했다)

★**페르소나를 1층에 넣고 싶어진다.** "너는 비서다, 짧게 말한다" — 이것도 늘 참인 규칙 같으니까.
아니다.

우리도 틀렸다. 계단을 두 번째 시스템에 적용하면서 역할 카드를 1층에 넣었다.
역할이 하나일 땐 괜찮아 보였다. **둘이 되자** 같은 안전 규칙이 두 카드에 복사됐고,
말투 하나 바꾸려고 **말투와 상관없는 규칙이 가득한 파일**을 열어야 했다.

★**정체성은 3층이다. 1층은 모든 역할이 공유하는 것만 둔다.**

| 1층에 두는 것 | 3층에 두는 것 |
|---|---|
| 정직 규칙, 파괴적 작업 전 확인, 사용자가 누구인지, 출력 형식 | 이 역할이 누구인지, 어떻게 말하는지, 무엇을 위한 것인지 |
| 모든 역할에 똑같다 | 역할마다 다르다 |

검사 도구가 1층에서 **정체성처럼 보이는 줄**을 잡아낸다. ★규격이 맞다고 이게 막히지 않는다 —
**검사가 막는다.** 3층을 *가리키는* 줄은 괜찮고, 카드 *자체가 되려는* 줄이 문제다.

## 두 번째 실수 — 문서에 적은 규칙은 시스템의 규칙이 아니다

1층은 "항상 참인 것"을 적는 자리지 **집행하는 자리가 아니다.**

우리는 역할 카드에 *"바꾸는 일은 제안만 하고 실행은 사람이 한다"* 라고 적어두고 안전하다고 믿었다.
아니었다. 같은 기능이 도구로도 열려 있었고, 그 도구를 부르면 그냥 실행됐다. 카드의 문장은 그 경로를
한 번도 지나지 않았다. 카드는 정직했고 배선이 정직하지 않았다.

고친 방법은 더 좋은 문장이 아니라 **말이 아닌 동작에 건 관문**이었다.

```
도구: 발행 중지(호스트)   -> 사람 승인 필요, 1회용, 10분 만료
도구: 발주(고객사)        -> 사람 승인 필요
도구: 상태 읽기(호스트)   -> 그냥 실행
```

앞서 실패한 시도와 갈린 지점이 둘이다.

- **요청문이 아니라 함수 호출에 건다.** 예전 판은 사용자의 말에서 "삭제·정지·재부팅" 을 정규식으로
  잡았다. 그 말이 들어간 평범한 문장까지 막혀서 결국 껐고, 그러자 아무것도 안 남았다. 동작에 걸면
  잘못 막히는 일이 거의 없다.
- **막히면 소리를 내라.** 승인이 없으면 "승인 필요" 를 돌려주고 사람이 보는 곳에 요청을 남긴다.
  조용한 실패는 영영 모르는 실패다.

1층에도 규칙은 그대로 둔다 — 에이전트가 알아야 하니까. 다만 이제 규칙이 **관문이기도** 하다.
1층에 제한을 적은 줄이 있으면 물어봐라. **모델이 이 줄을 무시하면 무슨 일이 일어나는가?**
답이 "아무것도 안 막는다" 면 그건 규칙이 아니라 바람이다.

## 4층은 사본이 아니라 주소가 필요하다

4층은 매 호출 끼워 넣는 층이라 기계마다 사본을 두고 싶어진다 — 색인도, 모델도, 열쇠도.
사본은 어긋나는 순간 전부 갈래가 된다.

찾아보는 도구 하나를 세 기계에 올리다 이 병을 만났다. 첫 판은 만든 기계에서만 돌았다. 조각을 복사해
"어디서나 되게" 만들었다면 일주일 안에 같은 질문에 세 가지 답이 나왔을 것이다. 대신 이렇게 했다.

- **쓰는 곳은 하나, 읽는 곳은 여럿.** 색인은 한 기계에서만 만들고 나머지로 밀어준다.
- **의존은 호출 시점에 푼다.** 임베딩 모델은 한 호스트에만 있다. 도구가 로컬을 먼저 찾고 없으면 그
  호스트로 간다. 명령은 어디서나 같고 출처는 하나다.
- **만든 기계 말고 모든 기계에서 확인해라.** 우리는 만든 기계에서 되는 걸 보고 "끝났다" 고 보고했다.
  검수 담당이 다른 기계에서 돌리자 즉시 실패했다. 두 기계에서 원인이 각각 달랐다 — 없는 라이브러리,
  그리고 한글 출력을 조용히 깨뜨리는 콘솔 인코딩.

4층이 기계에 매인 것을 끼워 넣는다면 **어느 기계가 주인인지 적어둬라.** "내 것에선 되는데" 는 상태가 아니다.

## 관문을 만든 뒤 — 반드시 확인할 넷

위 절대로 관문을 걸었다면 아직 절반이다. **관문 자체가 뚫린다.** 실제로 뚫리는 자리는 정해져 있으니
만든 날 이 넷을 확인해라.

**하나. 관문이 막힌 쪽에게 열쇠를 주고 있지 않은가.**
"승인 요청 3f2a1c 를 올렸습니다" 처럼 요청 번호를 돌려주면, 막힌 에이전트가 그 번호로 자기 요청을
자기가 승인한다. 번호는 **사람이 보는 알림에만** 두고 요청자에게는 주지 마라.

**둘. 승인자를 무엇으로 판정하는가. 그게 자기 신고면 한 단어로 뚫린다.**
환경변수로 판정하면 `BOT_ID=master` 를 앞에 붙이는 것으로 끝난다. ★그리고 이게 더 중요한데 —
그때 원장에 **"승인자: master" 라는 거짓 기록**이 남는다. 사고 후에 그 줄을 읽는 사람은 사람이
승인했다고 믿는다. **뚫리는 것보다 거짓 기록이 오래 남는다.**

**셋. 판정에 쓰는 데이터가 모든 기계에서 살아 있는가.**
판정을 로컬 파일로 옮기면 이번엔 반대로 **영영 안 열린다.** 우리 경우 그 파일이 한 기계에서 두 달,
다른 기계에서 넉 달 전에 멈춰 있었다. 방향은 안전하지만 **조용한 실패**라 이것도 사고다.
낡았으면 조용히 거절하지 말고 **"이 기계에선 승인이 도달할 수 없다" 를 소리내라.**

**넷. 중앙 저장소로 옮겨도 발신자 이름이 그냥 인자면 같은 자리다.**
키가 전원 공용이면 서버는 요청이 누구한테서 왔는지 알 방법이 없다.

★넷 다 구조가 같다. **신분이 자기 신고다.** 층을 옮겨도 안 바뀐다. 셋이 겹쳐 있기 때문이다.

```
에이전트가 셸을 쥔다   -> 환경변수·파일·명령을 마음대로 바꾼다
키가 전원 공용이다     -> 서버는 요청이 누구한테서 왔는지 알 수 없다
계정이 같다            -> 프로세스끼리 서로를 흉내낼 수 있다
```

이걸 진짜로 막으려면 **에이전트가 자격을 못 읽는 별도 계정의 프로세스**가 판정해야 한다.
규모에 안 맞으면 안 만들어도 된다. 다만 그때는 **반드시 이렇게 해라.**

**관문 코드 첫머리에 목적을 낮춰 적어라.**

```
막는다   : 정직한 에이전트의 실수와 오작동
못 막는다 : 작정하고 우회하는 에이전트
이건 실수 방지 장치지 보안 경계가 아니다. 이 위에 "그러니 안전하다" 를 쌓지 마라.
```

★**믿는 보호와 실제 보호의 간극이 장치의 구멍보다 위험하다.** 안 막힌 걸 막혔다고 믿으면 그 위에
다음 걸 쌓는다. 그리고 **원장은 거짓말하지 않게** 해라 — 검증 안 된 신분은 항상 *자칭* 으로 기록한다
(`by_claimed`, `verified: false`).

마지막으로 방법 하나. **자기가 만든 방어는 자기 시험을 통과한다.** 관문·인증·권한을 만들었으면
그날 안에 다른 사람이나 다른 에이전트에게 넘기고 **"검토해줘" 가 아니라 "뚫어봐라"** 라고 해라.
검토는 칭찬을 부르고 뚫기는 구멍을 부른다. 그리고 **실증을 요구해라** — "될 것 같다" 가 아니라
실제로 열고 흔적을 남기게.

## 층에는 값이 붙어 있다

같은 규칙을 1층에 문장으로 적을 수도 있고, 4층에 코드로 넣을 수도 있다. **결과가 다르다.**

| | 1층에 문장으로 | 4층에 코드로 |
|---|---|---|
| 비용 | 매 호출 다시 읽힌다 | 프롬프트 0글자 |
| 지켜지나 | 모델이 무시할 수 있다 | 무시할 수 없다 |

로그에 자격증명이 평문으로 들어가는 걸 막는다고 하자. 1층에 *"비밀을 로그에 남기지 마라"* 를 한 줄
적으면 매 호출 그 줄을 읽고, 그러고도 샌다. **나가는 길목 한 곳에 지우개**를 두면 프롬프트는 한 글자도
안 늘고 예외가 없다.

★그래서 "어느 층에 둘까" 는 위치 문제이면서 **비용 문제**다. 판단이 필요한 것은 1층에, 기계적으로
판정되는 것은 4층에. 이 질문을 먼저 해라 — **이건 읽혀야 하는가, 아니면 실행되어야 하는가?**

## 알려진 한계 (운영에 넣기 전에 읽을 것)
- 1층은 자라려 한다. 사건마다 "한 줄만 더"가 붙는다. 도구는 크기를 *보여줄* 뿐 막지 않는다.
- 사본은 어긋난다. 파일이 도착한 것과 프로세스가 그걸 로드한 것은 다르다. 배포 후 재시작하고 기동시각과 mtime을 대조하라.
- 절 매칭은 제목 부분일치다. 사람들이 묻는 말로 절 이름을 지어라.
- 라우팅은 일부러 키워드 기반이다(투명·디버깅 가능). 다른 표현은 놓친다.
- 1층에 비밀을 넣지 마라. 어디든 주입되고 어느 도구에든 붙는다. 키·토큰·고객명·내부 호스트명은 계단에 없어야 한다. 볼트를 가리키되 옮겨 적지 마라.
- 파일을 민 뒤엔 에이전트 프로세스를 재시작하라 — 바람이 아니라 명령으로. 재시작 후 프로세스 기동시각과 파일 mtime 을 대조. 기동 < mtime 이면 옛 기억으로 돌고 있는 것. 우리 첫날: 파일은 와 있는데 프로세스가 2.5시간 더 오래됐고, 에이전트가 낡은 장으로 답할 때까지 아무도 몰랐다.
- 대규모 코퍼스 검색을 대체하지 않는다. 팀 운영 지식(수십 파일)용이다.
